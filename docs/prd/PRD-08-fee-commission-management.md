# PRD-08 — Fee & Commission Management

## 1. Objective

Provide an Owner-only workspace to review, explain, adjust, and settle operator compensation generated by PRD-07.

## 2. Access

Default access: Owner only.

A future permission may expose an operator's own compensation summary, but operators must never gain unrestricted access to other operators' compensation or settlement controls unless explicitly designed.

## 3. Summary Information

The page should support selected-period summaries for:

- total pending
- total earned
- total paid
- total void/adjusted
- amount by operator
- amount by session type
- Studio Operator vs Recording Operator compensation

## 4. Operator View

Owner can select an operator and inspect:

- compensation entries
- source booking
- session type/package
- booking date
- compensation model
- calculation explanation
- expected amount
- status
- payout reference
- adjustments

## 5. Filtering

Required filters should include:

- date/period
- operator
- operator type
- status
- session type
- booking reference/search

## 6. Settlement / Payout

Owner can select eligible Earned entries and create a payout settlement.

Payout record stores:

- operator
- selected commission entry IDs
- total amount
- payout date
- payment method/reference
- notes
- actor/timestamp

Successfully settled entries become Paid and reference the payout.

## 7. Adjustment

Owner can create an adjustment with:

- linked entry/booking/operator
- amount delta or replacement semantics
- reason
- effective date
- actor

Adjustments are records; historical source entries should not be overwritten merely to make totals match.

## 8. Traceability

Every displayed compensation amount must allow navigation or inspection back to:

`Operator -> Commission Entry -> Booking -> Compensation Snapshot/Rule`

This is a hard requirement for resolving disputes.

## 9. Bookkeeping Integration

A payout can create/link an expense ledger entry according to the bookkeeping integration rule. Duplicate expense creation must be prevented through source IDs/idempotency checks.

## 10. UX Requirements

- Dense desktop table optimized for review.
- Clear status badges.
- Totals update with filters.
- Settlement confirmation shows selected entry count and exact total.
- Already-paid entries cannot be accidentally paid twice.
- Mobile view prioritizes summaries and individual operator detail rather than forcing a huge desktop table.

## 11. Acceptance Criteria

- Owner can see all generated compensation by operator and period.
- Owner can trace a fee to its source booking and calculation.
- Owner can settle multiple earned entries in one payout.
- Paid entries cannot be paid twice.
- Adjustments preserve the original entry history.
- Payout bookkeeping integration is traceable and idempotent.
